## 3. 已超越金山的部分（守住优势，不要回退）

这几项是本项目相对金山的**产品差异化**，后续改动务必保留：

1. **10 级难度细分**（`DifficultyScale`）— 金山只有简单/普通/困难三档。难度滑块可折叠，与三档按钮双向联动。
2. **评级 + 段位体系**（`GradeScale`）— 速度按「类型 + 等级」基准倍率折算 S/A/B/C/D，正确率作为**降级闸门**（防乱敲刷速度），再由 S 级次数推导段位（新手→入门→熟练→高手→大师）。金山的评价粗糙得多。
3. **键位热力图 + 薄弱键 Top**（`HistoryViewModel.BuildKeyAnalysis`）— 按「该按 A 却按成 B」归因到目标键，输出错误率排名 + 改进建议，样本 <5 次不参与排名（避免偶发误判）。**这是金山完全不具备的能力**，已达现代工具（如打字侠「错误热词分析」）水准。
4. **21 关渐进闯关 + 达标解锁**（`CourseLibrary`）— 5 阶段（指法 5 / 单键 4 / 单词 6 / 句子 3 / 文章 3），通关需同时满足正确率与评级。
5. **进步曲线 + CSV 导出** — 自绘 `TrendChart`，速度实线 + 正确率虚线 + 评级着色数据点。
6. **界面质感** — macOS 玻璃拟态（`GlassWindowBehavior` 附加属性）、亮色/护眼绿/暗黑三主题、全局键盘钩子驱动的虚拟键盘实时高亮。
7. **零外部资源依赖** — 图标全部 MDIX 矢量 `PackIcon`（无 emoji）、音效无音频文件、题库内置。

> 架构提醒（来自项目历史教训）：WPF 窗体加通用行为**必须用附加属性，不要继承自定义基类**，否则 XAML 与代码后置基类不一致会产生几十条连锁编译错误。这条已被验证过一次，P0 改动中若涉及窗体请沿用。

## 4. P0 — 优先做（对标完整性关键）

### P0-1　学前水平测试（定级测试）

- **对标**：金山的「学前测试」，让新手不用猜难度。
- **现状**：无任何测试/定级入口（已全项目检索确认）。
- **做法**：新增一个短测流程（60 秒英文 + 60 秒中文），用现有 `ITypingService.Evaluate` 得 WPM/KPM 与正确率，再经 `GradeScale` 反查，**推荐起始难度等级与建议跳过的课程关卡**。入口放首页。
- **复用**：`TypingViewModel` 的计时与评测逻辑、`GradeScale.GetBaselineSpeed` 反查等级。几乎不需要新算法。
- **工作量**：中（1 个新页面 + 1 个 VM）。

### P0-2　速度测试补「书本对照」模式

- **对标**：金山速度测试的三种方式之一，允许脱离屏幕对照、自选纸质素材。
- **现状**：只有屏幕对照；`CustomArticle` 支持导入自定义文章，但练习时仍全屏显示对照文本。
- **做法**：在 `TypingViewModel` 增加「隐藏对照正文」开关——隐藏后只显示进度与统计，用户对纸质/已读文本盲打；配合「练习前先看 15 秒」的预览倒计时。`CustomArticle` 的导入能力可直接当素材来源，**顺带实现金山「自选测试内容」**。
- **工作量**：小（1 个 bool 属性 + XAML 可见性绑定 + 预览计时）。

### P0-3　错词/错键靶向重练（错题本）

- **对标**：金山与现代工具都会把错题沉淀成针对性练习。
- **现状**：`TypingRecord.KeyStatsJson` 已在**逐键累积**对错，`HistoryViewModel` 已能算出薄弱键 Top —— **数据齐备，但只用于展示，没有回流到练习**。
- **做法**：新增「弱项专练」入口，从历史 `KeyStatsJson` 反查高频错词/错键，动态生成对照文本喂给 `TypingViewModel`。注意中文类练习目前不做键位采集（走输入法，物理键与目标字符无一一对应），因此**错词本初期只覆盖英文/单词/五笔**，中文需另走「错句重练」路径。
- **工作量**：中（生成器 + 入口），但**投入产出比最高**——数据已经在库里躺着。
- **附带**：可为热力图增加「一键专练这些键」按钮。

### P0-4　音效引擎替换（工程风险，非功能缺口）

- **问题**：`SoundService` 现用 `Console.Beep`（12 个音效方法、`readonly record struct Tone`、后台 `Task.Run` 播放）。公开资料普遍反映 `Console.Beep` 在 Windows 11 与部分声卡/虚拟音频环境下**无法发声或音量不可控**，且音色单一、无法做音量控制。这会让「音效开关」在部分机器上形同失效。
- **做法**：改为内嵌 WAV 资源 + `System.Media.SoundPlayer`（零新增依赖），或引入 NAudio 做低延迟混音。保留 `ISoundService` 的 12 个方法签名不动，只换实现——分层解耦在这里正好派上用场。
- **工作量**：小到中（换实现 + 准备 WAV 资源）。
- **验证建议**：在**目标用户的真实机器**上试听，而不是开发机。

## 7. 工程债务与技术风险（建议与 P0 并行处理）

### 7.1 无版本控制（**最高优先**）

`git status` 返回 `fatal: not a git repository`。整个项目**没有 git 仓库**。项目已迭代到 1.0.830 版本、有 100+ 源文件，却无任何历史可回退。

**建议**：任何 P0 改动前先 `git init`，写好 `.gitignore`（至少排除 `bin/`、`obj/`、`.vs/`、`publish/`、`*.db`、`.tmp/`），提交当前基线作为 `baseline` 提交。同时注意 `.tmp/` 下有 1.4MB 的 `wubi_map.tsv` 等中间产物、`publish/` 下有 170MB 的单文件 exe，都不应入库。

### 7.2 构建环境脆弱

本机复现了一个**真实踩坑**：直接 `dotnet build` 会失败于
`NuGet.targets: error : Value cannot be null. (Parameter 'path1')`。

根因是当前 shell 中 **`APPDATA` 与 `LOCALAPPDATA` 环境变量为空**（`$env:APPDATA` 返回空串），导致 NuGet 无法解析全局包目录与配置文件路径。补上这两个变量后还原与构建均正常。

另外本机装了 8.0.425 / 9.0.318 / 10.0.401 三个 SDK，**默认会选到 10.0.401**；需靠 `global.json` 固定到 8.0.425。

**建议**：在仓库根目录正式放置 `global.json`（现在它躺在 `.tmp/sdkpin/` 里），并把构建前置条件写入 README —— 否则换一台机器或换一个终端就会再次卡在同一个错误上。

### 7.3 README 与实际实现脱节

`README.md` 描述的是**早期形态**，与当前代码差异较大：

| README 描述 | 实际实现 |
| --- | --- |
| 内置 **4 款**游戏 | **6 款**（新增打气球、生死时速） |
| 3 个页面（录入/成绩/设置） | **7 个**模块（+ 首页、游戏乐园、学习园地、课程中心） |
| 无课程/闯关 | **21 关** 5 阶段闯关解锁 |
| 无评级/段位 | S/A/B/C/D + 5 级段位 |
| 无热力图 | 键盘热力图 + 薄弱键 Top |
| 音效 `Console.Beep` | 仍一致（**但见 P0-4 风险**） |
| 三套主题、字体设置 | 一致，另加玻璃拟态 |
| 虚拟键盘 | 一致，另加课程锁定模式 |

**建议**：README 以「当前实现」重写一遍功能章节，并把 §13 之后的历史改造记录保留为变更日志。文档失准会直接误导后续开发（我本轮就靠逐文件核对才确认了 21 关与 6 款游戏）。

### 7.4 无自动化测试

历史记录显示验证方式是「临时创建冒烟测试工程」再删掉。项目已含 6 种练习类型 × 10 级难度 × 21 关 × 6 款游戏的组合空间，**评级算法（`GradeScale`）、五笔编码判定（`EvaluateWubi`）、键位归因（`CollectKeyDeltas`）都是纯函数，非常适合单元测试**。

**建议**：建一个 `TypeMaster.Tests` 工程（xUnit），先覆盖 `GradeScale.Evaluate`、`TypingService.Evaluate/EvaluateWubi`、`CourseLibrary.IsUnlocked`、`DifficultyScale` 边界。这几处一旦回归，影响的是用户成绩的正确性，比 UI 问题严重得多。

### 7.5 其他小风险

- **全局键盘钩子**（`WH_KEYBOARD_LL`）用于虚拟键盘高亮，在受保护进程/部分安全软件下可能被拦截。建议保留「输入框 `KeyDown` 驱动高亮」作为降级路径，避免钩子失效时虚拟键盘完全不动。
- **中文练习无键位数据**：热力图对中文/中文词组恒为空，UI 已说明，但用户可能误以为坏了。建议空态文案里直接给出「中文走输入法，不采集物理键」的一句话解释 + 引导去做英文/五笔。
- **`TextLibrary.cs` 单文件 118KB**：题库与逻辑混在一个文件。若继续扩充题库（P1-2 拼音、P1-4 游戏词），建议按类型拆分文件。
- **窗口尺寸记忆**（`AppConfig.WindowWidth/Height`）在多显示器缩放（125%/150%）下可能需要校验。
