游戏增加动画效果、界面元素改为更丰富的卡通形象、增加游戏 BGM。

## 关键实测踩坑（**三个都是"不看就发现不了"的真 bug**）

### 1. `Console.Beep` → NAudio 重写（顺带修掉既有 P0 风险）
- 旧实现 12 个音效全靠 `Console.Beep`，在部分 Win11 / 虚拟声卡上不发声且无法控音量
- 新架构：**共享单例 `AudioEngine`**（一个 `WaveOutEvent` + 一个 `MixingSampleProvider`）
  - 为什么不每个声音各开设备：Windows 上多设备会互相抢占，出现爆音或丢音
  - `ISoundService` 的 12 个方法签名**完全不变**，调用方零改动
- 新增 `ToneSequenceProvider` 自合成音效（正弦 + 3ms 淡入 / 12ms 淡出，消除起音爆音）
- **分层要求**：`TypeMaster.Services` 不能引用 WPF。淡入淡出原用 `DispatcherTimer` 编译失败，改 `System.Threading.Timer`
- **TFM 必须改 `net8.0-windows`**：NAudio 的 WaveOut 与 SAPI 都是 Windows 专有 API，纯 `net8.0` 下不可见

### 2. **循环播放静默失效**（最隐蔽）
- 现象：BGM 只播一遍就停，没有任何报错
- 根因：`LoopSampleProvider` 接受任意 `ISampleProvider`，运行时用类型判断能否定位；
  传入不可定位的源（如直接传 `AudioFileReader`）时循环静默失效
- 修复：**构造参数直接要求 `AudioFileLoopProvider`**，让误用在编译期被挡住
- 验证：修复后 lobby 源 15.51s → 循环读到 38.82s（2.5 倍），7 首全部 OK

### 3. **精灵 pack:// 路径全部解析失败**（会导致 9 个角色全空白）
- 实测对比（决定性）：
  - `pack://application:,,,/Assets/Sprites/ship.png` → **0/9 成功**
  - `pack://application:,,,/TypeMaster;component/Assets/Sprites/ship.png` → **9/9 成功**
- 相对写法依赖 WPF 对"入口程序集"的识别，单文件发布等场景不可靠
- **规则：引用程序集内资源一律显式写程序集名**（程序集名见 App.csproj 的 AssemblyName=TypeMaster）

### 4. 音乐响度：软限幅
- 初次生成 5 首削波（峰值 1.23~1.31 > 1.0），16bit 量化与 MP3 编码会产生刺耳失真
- 只做归一化不够（峰值相对凸起仍在），需**软限幅**：超阈值部分按 tanh 压缩
- 修复后 7 首峰值统一 0.92、削波 0

## 动画增强
- 目标角色：`BackEase` 缩放入场（挤压回弹）+ 待机上下浮动 + 锁定时脉动放大
- **消散动画**：被消灭时原地复制精灵，先放大 1.24 倍（打击感）再旋转缩小上飘淡出
  - 为什么复制一份：目标被消灭后立即从 `Targets` 移除，模板随之销毁，动画播不完
  - `TransformGroup.Children[0]` 这类带索引的 PropertyPath 在 WPF 中不稳定，
    改为**直接以 Transform 对象为动画目标**（新增 `AddTransformDouble`）
- 赛跑选手：上下颠动 + 前倾摆动，两者周期略不同避免机械感

## 设置项
`AppConfig` 新增 `EnableMusic` / `MusicVolume`(默认 55) / `SoundVolume`(默认 80)，
经 `SqliteSchemaUpgrader` 为旧库非暴力补列；设置页加开关与两个音量滑块，改动即时生效。
