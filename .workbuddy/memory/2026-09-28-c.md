# 2026-09-28（下午续）TypeMaster 游戏结束弹框被遮挡 + 单文件发布修复

## 问题 1：游戏结束时弹框被遮挡

### 定位方法
不靠猜——**把「游戏结束」状态真实渲染成 PNG**，直接看才发现问题。
量化结果（修复前）：

| 窗口尺寸 | 游戏区高度 | 卡片需要 | 实际渲染高度 | 结果 |
| --- | --- | --- | --- | --- |
| 1280x800 | 352 | 302 | 302 | 正常 |
| **1100x720（默认）** | **272** | **302** | **270** | 裁掉 32px |
| **900x600** | **152** | **302** | **150** | 只剩一半 |

截图证实：「再来一局」按钮只剩一半，**「返回游戏厅」完全看不见**。

### 根因（两个叠加）
1. **结构问题（主因）**：结算遮罩写在 `PlayArea` 内部，而 `PlayArea` 是
   `Border` 且设了 `ClipToBounds="True"` → 游戏区高度不足时弹框被硬裁。
   **在 PlayArea 里怎么调都治不好**，必须移出去。
2. **层级倒挂**：结束遮罩 `ZIndex=55`，但庆祝闪光层是 `60`、趣味提示气泡是 `100`，
   两者都盖在遮罩之上。

### 修复
把结算遮罩**提升为整页模态层**（最外层 Grid）：
- `Grid.RowSpan="3"` 覆盖顶部信息栏 / 游戏区 / 底部输入区
- `Panel.ZIndex="200"` 高于闪光层(60)与趣味提示(100)
- 卡片套 `ScrollViewer` + `MaxHeight` 绑页面高度 → 极矮窗口也能滚动，不再被裁
- 半透明遮罩层同时挡住底层鼠标操作，形成真正的模态

顺带修掉一个观感问题：`MaterialDesignOutlinedButton` 的描边在浅色卡片上对比度太低，
截图里「返回游戏厅」看着像禁用的空按钮 → 改为浅灰实底 + 深色文字。

### 验证
在 **5 种窗口尺寸 × 2 种游戏** 下重新渲染确认：
1100x720 / 900x600 / 1280x800 / 1100x560 / 820x520 —— 全部完整居中显示。
最小 820x520 下两个按钮依然完整可见。

## 问题 2：单文件 exe 拷到别处会崩溃

### 现象
把 `publish\TypeMaster.exe` 单独复制到空目录运行 → 进程立刻退出，
stderr 报 `DllNotFoundException` at `SetWindowLongPtrWndProc`。

### 根因
`PublishSingleFile=true` **默认不把原生库打进 exe**。
`publish` 目录里的 `wpfgfx_cor3.dll`、`PresentationNative_cor3.dll`、
`vcruntime140_cor3.dll`、`D3DCompiler_47_cor3.dll`、`PenImc_cor3.dll`、`e_sqlite3.dll`
（共 9.4MB）是 exe 运行所必需的。用户只拷 exe 就会崩。

### 修复
发布命令加 `-p:IncludeNativeLibrariesForSelfExtract=true`，并加
`-p:DebugType=None -p:DebugSymbols=false` 去掉 pdb。

### 验证
复制到空目录（**只有 exe，无任何 DLL**）→ 进程存活、窗口响应、**stderr 为空**。

## 交付命令（以后发布就用这条）
```powershell
$env:APPDATA='C:\Users\HTY\AppData\Roaming'
$env:LOCALAPPDATA='C:\Users\HTY\AppData\Local'
$env:DOTNET_ROOT='C:\Program Files\dotnet'
$env:NUGET_PACKAGES='C:\Users\HTY\.nuget\packages'
cd 'E:\PrivateProjects\Private\TypeMaster\.tmp\sdkpin'   # 该目录有 global.json 固定 SDK 8.0.425
dotnet publish 'E:\PrivateProjects\Private\TypeMaster\src\TypeMaster.App\TypeMaster.App.csproj' `
  -c Release -r win-x64 --self-contained true `
  -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:DebugType=None -p:DebugSymbols=false `
  -o 'E:\PrivateProjects\Private\TypeMaster\publish'
```
产物：`publish\TypeMaster.exe`（约 175MB，单文件自包含，可独立运行）

## 经验
- **UI 遮挡类问题不要靠读代码猜**：把目标状态渲染成 PNG 再目测，一次就能定位。
  本轮两次修复都靠这个手段确认（修复前看到按钮被切掉，修复后确认完整）。
- **用户说"被遮挡"时，除了检查 ZIndex，一定要检查 ClipToBounds**——
  本例主因是裁剪而非层级，只调 ZIndex 是治不好的。
- `PublishSingleFile` 不等于"一个 exe 就能跑"，原生库需要额外开关。
