# 2026-09-28（晚）打字练习不换行 + 游戏词库扩充

## 问题 1：打字练习打完一行就停

### 根因（实测确认，非推测）
`TextLibrary.LevelTargetLengths` 旧值为 `{40, 70, 110, 160, ...}`，
**等级 1 只有 40 字符 ≈ 一行**。截图那段正是 39 字符（内置文章「一年级·四季·春天来了」被截断）。

### 修复（三层，缺一不可）
1. **加长目标长度**：`40/70/110...` → `80/140/200/280/360/450/550/660/800/950`
2. **拼接不同文章**：`FitLength` 原本在长度不足时**把同一篇再拼一遍**，
   实测会产出「太阳当空照…（若干字）…太阳当空照…」这种肉眼可见的重复。
   改为从同难度池里抽**不同**文章续接。
3. **自动续接**（真正的"继续"）：抽出通用的 `AutoExtendIfNeeded()`。
   项目里原本**只有测速模式**有这机制（`EnsureSpeedTextLongEnough`），
   现推广到全部练习类型——剩余不足 160 字符时自动追加**新随机内容**。
   关卡模式 / 指定文章 / 五笔模式**不续接**（保证考核公平与尊重用户选择）。
4. **对照区自动滚动**（`ScrollCaretIntoView`）：`DisplayBox` MaxHeight 180→260，
   并让视口跟随当前输入位置。**这步不能省**——文本再长，视口不动用户照样"看不到下文"。
   > 注意：`RichTextBox` 没有 `Viewport` 属性（那是 ScrollViewer 的），
   > 要用 `VerticalOffset + ActualHeight` 自行换算可视区间。

## 问题 2：游戏单词重复

### 根因（实测确认）
游戏词库仅 **66 个词**（简单 24 / 普通 22 / 困难 20）。
实测连抽 20 次只有 **14 个不同词**。

### 修复
用 **Google 万词表**（google-10000-english-no-swears，按词频降序）替换：

**过滤规则**（每轮抽查后补强，共五层）
1. 1-2 字母词（游戏是"锁定首字母后逐字匹配"，`a`/`an`/`it` 无练习价值且抢锁）
2. 黑名单：敏感词 / 宗教 / 政治战争 / 消极疾病法律 / 缩写 / 技术网络词 / 品牌机构 / 地名人名日期
3. 形态规则：连续 4 个以上辅音、无元音、元音占比 < 25%（排除 `xhtml`/`sbjct`/`cms` 这类碎片）
4. 三连相同字母
5. **每档只取词频最高的前 N 个** —— 这是最有效的一招：
   词表按词频降序，**噪声全堆在长尾**，与其无限加黑名单，不如从源头砍掉长尾

**分档**（与 `TypingGameEngine.MaxWordLength` 对齐）
- 简单 3-5 字母 1500 词 ｜ 普通 6-8 字母 2000 词 ｜ 困难 9+ 字母 1200 词

**落地方式**：生成 `GameWords.cs`（C# 源数组，非嵌入资源）——
与项目既有风格一致（TextLibrary 里题库本来就是硬编码 C#），编译期就位、零启动开销、不怕单文件发布丢资源。

### 实测效果
| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 词库总量 | 66 词 | **4700 词（71 倍）** |
| 抽 200 次不同词 | —（池太小） | **185~192 个（92~96%）** |
| 引擎抽 300 次不同词 | 14/20 | **247~282 个** |
| 等级 1 文本长度 | 40 字符 | **80 字符** |
| 等级 10 文本长度 | 600 | **950** |
| 重复拼接 | 会把同篇拼两遍 | **0 次** |

## 经验
- **"打完就停"要同时修三处**：文本长度、续接机制、视口滚动。
  只改长度只是把问题往后推；只改续接而视口不动，用户依然看不到下文。
- **过滤长尾比加黑名单有效**：词表本身按词频排序，噪声集中在尾部，
  设一个"取前 N"的闸门比逐个拉黑省力得多。
- `RichTextBox` 无 `Viewport`，判断可视区间得用 `VerticalOffset + ActualHeight`。
- publish 前若 exe 正在运行会报 MSB4018（文件占用），先关进程再发布。
